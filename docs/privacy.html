Privacy policy

Effective date: September 21, 2026

This policy describes ScrollBill version 0.1.1 as currently implemented. ScrollBill turns Android application usage history into a local weekly report and an optional shareable receipt.

Short version: ScrollBill processes usage information on your Android device. It has no account, backend, analytics, advertising, or Internet connection. Nothing is uploaded by ScrollBill.

What ScrollBill accesses

ScrollBill uses Android's special Usage Access setting to read application foreground-usage history for the last seven completed local calendar days. It also reads application names and icons when Android makes that metadata available for presenting your report.

Usage Access is controlled by Android system settings. You can grant or revoke it at any time.

How information is processed

Usage records are queried and aggregated locally. ScrollBill does not send usage durations, package identifiers, reports, or installed-app inventories to a ScrollBill server because no server or network client exists.

ScrollBill does not use a database for usage history or report history. A generated receipt image is temporarily written to the app's private cache so Android can pass it to a destination you select.

Sharing

Sharing is explicitly user initiated. When you tap Share receipt, Android opens its Sharesheet and lets you choose another application. ScrollBill provides the image through a temporary protected content URI. ScrollBill does not automatically upload, publish, or choose a destination. The receiving application's handling of the image is outside ScrollBill's control.

What ScrollBill does not do

  • Require an account, email address, or login
  • Use analytics, advertising, tracking, or crash-reporting SDKs
  • Upload usage information or operate a cloud backend
  • Request contacts, location, storage, notification access, or accessibility access
  • Sell personal data
  • Provide medical, addiction-treatment, parental-control, or app-blocking functionality

Permissions and visibility

The app declares PACKAGE_USAGE_STATS, which is a special Android access rather than a normal runtime permission. It also declares a narrow launcher-intent package-visibility query so normal launchable applications can provide labels and icons. It does not request QUERY_ALL_PACKAGES or INTERNET.

Retention

ScrollBill does not retain a usage database, installed-app inventory, or report history. The current receipt may remain temporarily in the app's private cache and is overwritten on a later generation. Android and the application you choose to share with may have their own retention behavior.

Contact

Privacy questions can be directed to the ScrollBill project owner through the contact channel associated with the application's distribution account.
